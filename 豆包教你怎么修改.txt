# 你的Agent Skill两大问题根源+完整修复方案
## 一、问题1：数据源只有arXiv，检索范围极窄
### 核心底层原因
1. **Skill工具仅封装了arXiv单一API**
你只写了`arXiv search`这一个工具函数，没有接入其他学术数据库接口（Semantic Scholar、OpenAlex、Crossref、PubMed、Springer等），Agent没有其他检索入口，自然只会搜arXiv。
2. **Agent系统提示词（System Prompt）未要求多源检索**
系统指令只写了“去arXiv搜索论文”，没有告知模型**同时检索多数据库、合并去重**，LLM只会调用唯一可用工具。
3. **缺少多数据源聚合中间层**
没有统一文献标准化工具（ScholarFlux/QuasarX），多库API格式、分页、限流逻辑复杂，你没做兼容封装，Agent无法自动切换数据源。
4. **没有多轮检索分支逻辑**
Skill是单一步骤：调用arXiv→返回结果，不存在“arXiv结果不足→自动补充检索其他库”的判断分支。

### 修复方案（可直接落地）
1. **新增多学术检索Tool（并行工具）**
在Skill里同时封装多个免费学术API：
- arXiv（预印本）
- Semantic Scholar（全领域，含已刊论文、引用）
- OpenAlex（开源综合文献库）
- Crossref（期刊正式发表论文）
统计领域额外加：PubMed、JASA期刊接口
示例工具结构：
```python
# 三个独立可调用工具
search_arxiv(query)
search_semantic_scholar(query)
search_openalex(query)
```
2. **改写System Prompt强制多源检索**
```
你的任务：全面检索统计学领域近7天论文
规则：
1. 必须同时调用arXiv、Semantic Scholar、OpenAlex三个检索工具并行搜索；
2. 根据DOI/标题相似度自动合并重复论文；
3. 区分预印本(arXiv)与同行评审期刊文献，分开标注来源；
4. 若单库返回少于8篇，自动生成同义关键词二次扩搜。
```
3. **增加统一数据归一化函数**
统一所有库返回字段：标题、作者、摘要、发表时间、DOI、来源、链接，自动去重，避免多库结果混乱。
4. **可选：集成聚合SDK简化开发**
使用scholar-flux一键对接7大数据库，不用手动写每个API的请求、限流、解析逻辑。

## 二、问题2：只照搬原文，不会总结概括
### 核心底层原因
1. **Skill工作流只有「检索」单一步骤，缺少「摘要加工」子步骤**
当前Workflow：用户提问 → 调用arXiv API → 直接返回原始摘要文本
缺少**检索完成→批量精读摘要→LLM生成结构化总结**的第二阶段Skill，模型拿到原始数据直接输出，没有提炼环节。
2. **Prompt未下发强制总结指令，只要求返回文献列表**
系统提示只规定“返回检索到的论文信息”，没有明确要求**提炼核心方法、创新点、结论、研究局限**，LLM默认直接复制原始abstract。
3. **工具调用逻辑割裂：检索工具与LLM生成逻辑分离**
检索函数只负责拉取数据，没有把论文列表回传给大模型做二次处理；Agent拿到工具返回值直接输出，不再走推理总结链路。
4. **无结构化输出约束**
没有指定总结输出格式（分点、分类、领域综述），LLM无约束时倾向原文搬运。

### 修复方案（分三层改造）
#### 1. 拆分双阶段Workflow（关键）
原错误流程：
`用户指令 → 调用arXiv检索 → 直接输出原始摘要 + 发邮箱`

修正完整流程（两个Skill串联）：
1）检索Skill：并行多数据库拉取论文元数据、去重过滤近7天文献
2）总结加工Skill：把全部论文信息送入LLM批量生成结构化综述
3）邮件分发Skill：将**总结报告+原文链接**打包发送邮箱

#### 2. 新增专用总结Prompt模板（嵌入Skill）
```
你是统计学专业科研助理，基于下面多篇论文摘要完成文献综述，严格遵守要求：
1. 对每篇论文单独总结：研究目标、核心统计方法、创新点、实验/实证结论；
2. 横向汇总：近7天该领域整体研究热点、方法演进脉络；
3. 禁止直接复制原文句子，全部用自己的话重述概括；
4. 输出结构化：分【单篇论文解读】【领域整体综述】两大部分；
5. 文末附上每篇论文来源、DOI、原文链接。
待处理论文列表：{paper_list}
```
#### 3. 强制Agent二次推理，不直接返回工具原始结果
修改Agent执行逻辑：
- 所有检索工具返回结果**不能直接作为最终输出**；
- 必须把检索结果作为上下文，再执行一次LLM生成任务，生成总结文本后再触发发邮件。

#### 4. 增加全文精读增强总结（可选进阶）
如果需要深度概括，新增`download_pdf + text_extract`工具，读取论文全文后再总结，仅靠摘要会概括偏浅。

## 三、完整改造后Skill整体架构
### Skill1：多源文献检索工具
- 并行调用arXiv、Semantic Scholar、OpenAlex
- 过滤近7天、统计学分区、去重、排序
- 输出标准化论文元数据列表

### Skill2：文献批量总结工具
- 接收检索结果
- 调用LLM结构化提炼单篇+领域综述
- 生成完整可直接邮件发送的报告文本

### Skill3：邮件发送工具
- 接收总结报告+论文链接清单
- 自动填充邮件标题、正文、附件链接，推送指定邮箱
